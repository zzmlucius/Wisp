# 混合测试第一版参数

供 Codex 更新现有混合测试：接口、随机轮次、输出、采样、调度器控制和清理沿用已有实现；本文件覆盖旧的 RPS、运行时长和后台线程默认值，不自动增加测试次数。

## 参数

前台固定 **1000 RPS**，前后台各运行 **60 秒**；后台先用 **14 个线程**持续尽力计算。前台请求 p99 上限仍为 **10000 µs（10 ms）**。

前台 schbench（以下按原前台工作线程数为 14 设置；若原实测不同，保持原线程数并记录）：

```bash
schbench -m 1 -t 14 -r 60 -F 256 -n 5 -s 100 -R 1000 -w 0 -z 0
```

后台 sysbench CPU：

```bash
sysbench cpu --threads=14 --cpu-max-prime=20000 --time=60 --events=0 --rate=0 --warmup-time=0 --report-interval=1 run
```

- 由混合脚本共同门控、近同时启动；前后台共享原测试 CPU 范围，普通优先级，不额外设置 nice、权重或配额。不要顺序执行两条命令，不增加内部预热。
- 后台固定线程数、单事件计算内容和时长；不限制每秒速率或事件总数，比较实际 `events/s`。核对本地版本 help，保存实际命令。
- 前台达标条件：实际平均 RPS 与 1000 的偏差不超过 2%，且请求 p99≤10000 µs。2% 为本版预设容差；超限保留并标记未达标，不因此将技术有效的记录删除。

## 总运行时间

| 执行范围 | 正式负载时间（约） |
|---|---:|
| `./mixtest`：当前策略一次 | 60秒 |
| `./mixtest 1`：四策略各一次 | 240秒＝4分钟 |
| `./mixtest n`：四策略各n次 | 240n秒＝4n分钟 |
| `./mixtest 3`：共12次 | 720秒＝12分钟 |

每次前后台并发运行，因此是约60秒，不是120秒。实际整批耗时还要加准备、策略切换、稳定等待、冷却和收尾；预实验及单独运行基线另计。运行/统计窗口核验及任一负载失败时的双方清理沿用已有流程。

参数参考：[schbench](https://github.com/masoncl/schbench)、[sysbench](https://github.com/akopytov/sysbench)。以上负载组合为本项目待实测起点。
